Kubernetes Volume Snapshots 详解

发表于2026-08-07|Kubernetes
|总字数:1.4k|阅读时长:5分钟|浏览量:

在 Kubernetes 中，Volume Snapshots（卷快照） 用于为持久卷（PV）创建时间点副本，是备份恢复、数据克隆等场景的基础能力。这一特性通过 CSI（容器存储接口） 实现，并引入了一组新的 API 资源来管理快照的生命周期。本文梳理卷快照的核心概念、工作原理与使用方法。

一、核心概念与 API 资源

1.1 三个核心资源的关系

卷快照由三个 CRD 协作完成，它们的关系与 PVC / PV 高度相似：

graph LR
    A[VolumeSnapshotClass] -->|定义后端配置| B[VolumeSnapshot]
    B -->|绑定| C[VolumeSnapshotContent]
    C -->|指向| D[存储后端实际快照]
  • VolumeSnapshotClass 类比 StorageClass——定义用哪个后端、什么删除策略。
  • VolumeSnapshot 类比 PVC——用户发起的「我要一份快照」的请求（命名空间级）。
  • VolumeSnapshotContent 类比 PV——系统创建的、代表后端实际快照的对象（集群级）。

1.5 CSI 与卷快照

CSI（容器存储接口） 是 Kubernetes 与存储系统之间的标准接口。支持快照功能的 CSI 驱动需实现以下接口：

  • CreateSnapshot：创建卷快照
  • DeleteSnapshot：删除卷快照
  • ListSnapshots：列出 / 查询快照

必备组件：

  1. CSI Driver：如 AWS EBS CSI Driver、Ceph CSI 等，负责真正与存储后端交互。
  2. snapshot-controller：Kubernetes 官方的控制器，监听 VolumeSnapshot / VolumeSnapshotContent，负责二者的绑定与状态维护。
  3. csi-snapshotter：作为 Sidecar 与 CSI Driver 部署在一起，负责把绑定好的快照请求翻译成对 CSI Driver 的 gRPC 调用。

二、卷快照工作流程

2.1 创建快照流程

创建快照涉及两个组件的协作：snapshot-controller 负责 VolumeSnapshot 与 VolumeSnapshotContent 的绑定，csi-snapshotter Sidecar 负责调用 CSI Driver 真正在后端创建快照。

sequenceDiagram
    participant User as 用户
    participant API as API Server
    participant Ctrl as snapshot-controller
    participant Sidecar as csi-snapshotter
    participant Driver as CSI Driver
    participant Backend as 存储后端

    User->>API: 创建 VolumeSnapshot
    API->>Ctrl: 感知到新的 VolumeSnapshot
    Ctrl->>API: 创建并绑定 VolumeSnapshotContent
    API->>Sidecar: 感知到 VolumeSnapshotContent
    Sidecar->>Driver: gRPC 调用 CreateSnapshot
    Driver->>Backend: 创建实际快照
    Backend-->>Driver: 返回快照 ID
    Driver-->>Sidecar: 返回成功
    Sidecar->>API: 更新 VolumeSnapshotContent 状态
    API->>User: VolumeSnapshot 状态变为 readyToUse

三、关键功能与应用场景

3.1 备份与恢复

  • 自动化备份：结合 CronJob 定期创建 VolumeSnapshot。
  • 灾难恢复：通过 dataSource 字段从快照恢复 PVC。

3.2 测试与开发

  • 克隆生产数据：基于生产环境的卷快照创建测试环境。
  • 版本回滚：应用升级失败时恢复到之前的状态。

3.3 数据迁移

  • 跨集群迁移：将快照复制到目标集群并恢复。
  • 存储类型转换：例如从 AWS EBS 迁移到 GCE PD。

五、小结

  • 卷快照由三个资源协作：VolumeSnapshotClass（定义后端与删除策略）、VolumeSnapshot（用户请求，类比 PVC）、VolumeSnapshotContent（实际快照，类比 PV）。
  • 底层依赖 CSI，运行时由 snapshot-controller（负责绑定）与 csi-snapshotter Sidecar（负责调 CSI Driver）协作完成。
  • 恢复卷的方式是创建新 PVC 并用 dataSource 指向快照，常用于备份恢复、数据克隆与迁移。
