Linux 控制组（Cgroups）

Namespace 解决了”能看到什么”的问题，而 Cgroups 解决的是”能用多少”的问题。两者共同构成了容器的底层基石。

Cgroups 是什么

Cgroups（Control Groups，控制组）是 Linux 内核提供的一种机制，用于将一组进程组织到层次化的组中，并对每个组施加资源限制、优先级分配、记账和控制器。

简单来说，Cgroups 让你可以声明：这组进程最多只能用 2GB 内存、1 个 CPU 核心——超出就会被 OOM Kill 或限流。

Cgroups 的四大功能

功能 说明 示例
资源限制（Resource Limitation） 限制进程组使用的资源上限 内存不超过 512MB
优先级分配（Prioritization） 分配更多 CPU 或 I/O 带宽给某些组 高优先级容器获得更多 CPU 时间片
记账（Accounting） 统计进程组使用的资源量 计费、监控
控制（Control） 冻结、重启进程组 快照、迁移

Cgroups v1 vs v2

Linux 存在两个版本的 Cgroups，理解它们的区别非常重要：

特性 Cgroups v1 Cgroups v2
层次结构 每个子系统独立一棵树 统一的单一层次树
接口路径 /sys/fs/cgroup/<subsystem>/ /sys/fs/cgroup/
控制器挂载 各控制器独立挂载 所有控制器统一挂载
进程归属 同一进程可属于不同 cgroup 一个进程只能属于一个 cgroup
内核支持 Linux 2.6.24（2008） Linux 4.5（2016），默认从 4.5+ 开始
Docker 默认 早期版本使用 Docker 20.10+ 默认使用 v2

Docker / Kubernetes 现在默认使用 Cgroups v2，但 v1 仍在大量生产环境中运行。

Cgroups v1 子系统（控制器）

Cgroups v1 中，每个子系统（也叫控制器）负责一种资源的管控：

子系统 作用
cpu 限制 CPU 使用时间比例
cpuset 绑定到指定 CPU 核心和内存节点
memory 限制内存和 swap 使用量
blkio 限制块设备 I/O 带宽
devices 控制对设备的访问权限
net_cls 标记网络包，配合 tc 做流量控制
pids 限制进程组内的进程数量
freezer 冻结/恢复进程组

Docker 如何使用 Cgroups

当运行 docker run -m 512m nginx 时，Docker 实际上做了：

  1. 在 /sys/fs/cgroup/memory/ 下创建一个以容器 ID 命名的 cgroup
  2. 将 memory.limit_in_bytes 设置为 512m

小结

  • Namespace：让进程”看”不到别人 → 视图隔离
  • Cgroups：让进程”用”不了太多 → 资源限制
  • UnionFS：让镜像”叠”起来 → 轻量分层

三者缺一不可，共同构成了容器的技术底座。
