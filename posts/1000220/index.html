Kubernetes CSI 详解：架构、组件与工作原理

发表于2026-08-06|Kubernetes
|总字数:3k|阅读时长:10分钟|浏览量:

一、CSI 概述

Container Storage Interface（CSI）是一套标准化接口，用于定义容器编排系统（如 Kubernetes）与存储供应商之间的交互方式。它的目标是让存储供应商开发的插件能够兼容多个容器编排系统（Kubernetes、Mesos、Swarm 等），从而简化存储资源的管理和使用。

在 Kubernetes 中，CSI 提供了一种标准方式，用于与第三方存储供应商（如 NFS、AWS EFS、Ceph、GlusterFS 等）对接，实现存储卷的创建、挂载、卸载等操作。CSI 的引入取代了旧的 FlexVolume 插件机制，提供了更灵活、更强大的存储管理能力。

二、CSI 系统架构

CSI 在 Kubernetes 中分为控制端和节点端两部分：

Controller Server（控制服务器）

  • 功能：负责存储卷的生命周期管理，包括卷的创建、删除、挂载、卸载等操作。
  • 部署方式：通常以 StatefulSet 或 Deployment 的形式运行，确保高可用性和唯一性。
  • 组件：
    • CSI 驱动容器：由第三方存储供应商提供，实现 CSI 接口的 IdentityServer 和 ControllerServer。
    • Sidecar 容器（如 external-provisioner、external-attacher 等）：负责与 Kubernetes 组件（如 kube-controller-manager）通信，触发 CSI 驱动的操作。

Node Server（节点服务器）

  • 功能：负责节点级别的存储卷挂载和卸载操作。
  • 部署方式：以 DaemonSet 的形式运行，确保每个节点上都有 CSI 插件实例。
  • 组件：
    • CSI 驱动容器：由第三方存储供应商提供，实现 CSI 接口的 IdentityServer 和 NodeServer。
    • Sidecar 容器（如 node-driver-registrar）：负责与 kubelet 通信，注册 CSI 驱动。

三、CSI 组件构成及功能

（一）CSI Controller

CSI Controller 是 CSI 插件的控制端，负责存储卷的生命周期管理。其主要组件包括：

Sidecar 容器

  • external-provisioner：监听 PersistentVolumeClaim（PVC）的变化，触发 CSI 驱动的 CreateVolume 和 DeleteVolume 操作，实现存储卷的创建和删除。
  • external-attacher：监听 VolumeAttachment 的变化，触发 CSI 驱动的 ControllerPublish 和 ControllerUnpublish 操作，实现存储卷的挂载和卸载。
  • external-resizer：监听 PersistentVolumeClaim 的大小变化，触发 CSI 驱动的 ResizeVolume 操作，实现存储卷的容量调整（现已 GA）。
  • external-snapshotter：监听 VolumeSnapshot 的变化，触发 CSI 驱动的 CreateSnapshot 和 DeleteSnapshot 操作，实现存储卷的快照管理（现已 GA）。

CSI Driver 容器

由第三方存储供应商提供，实现 CSI 接口。通过 Unix Domain Socket 与 Sidecar 容器通信，完成具体的存储卷操作。

部署建议：CSI Controller 通常以 StatefulSet 或 Deployment 的形式运行，副本数设为 1，以确保唯一性。

（二）CSI Node

CSI Node 是 CSI 插件的节点端，负责节点级别的存储卷管理。其主要组件包括：

Sidecar 容器

  • node-driver-registrar：将 CSI 驱动注册到 kubelet，监听 kubelet 的操作请求，触发 CSI 驱动的节点端接口（如 NodePublishVolume、NodeUnpublishVolume 等）。

CSI Driver 容器

由第三方存储供应商提供，实现 CSI 接口。接收 kubelet 的调用，完成存储卷的挂载、卸载等操作。

通信方式

  • node-driver-registrar 与 kubelet 通过 Unix Domain Socket 通信。
  • CSI Driver 容器与 kubelet 通过另一个 Unix Domain Socket 通信，并挂载 kubelet 的工作目录（默认为 /var/lib/kubelet），用于管理 Pod 的 Volume。

部署建议：CSI Node 以 DaemonSet 的形式运行，确保每个节点上都有 CSI 插件实例。

四、CSI 接口介绍

第三方存储厂商需实现 CSI 插件的三大接口：IdentityServer、ControllerServer、NodeServer。

IdentityServer

IdentityServer 主要用于认证 CSI 插件的身份信息。

ControllerServer

ControllerServer 主要负责存储卷及快照的创建/删除以及挂接/摘除操作。

NodeServer

NodeServer 主要负责存储卷挂载/卸载操作。

五、CSI Sidecar 组件介绍

为使 Kubernetes 适配 CSI 标准，社区将与 Kubernetes 相关的存储流程逻辑放在了 CSI Sidecar 组件中。

1. Node Driver Registrar

功能：将外部 CSI 插件注册到 kubelet，从而使 kubelet 通过特定的 Unix Domain Socket 来调用外部 CSI 插件函数（如 NodeGetInfo、NodeStageVolume、NodePublishVolume、NodeGetVolumeStats 等）。

原理：通过 kubelet 外部插件注册机制实现注册，注册成功后：

  • 为本节点 Node 资源打 annotation：调用外部 CSI 插件的 NodeGetInfo 函数，其返回值 nodeID、driverName 作为值用于 csi.volume.kubernetes.io/nodeid 键。
  • 更新 Node Label：将 NodeGetInfo 返回的 AccessibleTopology 值用于节点的 Label。
  • 更新 Node Status：将 NodeGetInfo 返回的 maxAttachLimit（节点最大可挂载卷数量）更新到 Status.Allocatable: attachable-volumes-csi-[driverName]=[maxAttachLimit]。
  • 更新 CSINode 资源（没有则创建）：将 driverName、nodeID、maxAttachLimit、AccessibleTopology 更新到 Spec 中（拓扑仅保留 Key 值）。

2. External Provisioner

功能：创建/删除实际的存储卷，以及代表存储卷的 PV 资源。

原理：启动时需指定参数 --provisioner，该参数指定 Provisioner 名称，与 StorageClass 中的 provisioner 字段对应。启动后会 watch 集群中的 PVC 和 PV 资源。

对于 PVC 资源，判断其是否需要动态创建存储卷：

  • PVC 的 annotation 中是否包含 volume.beta.kubernetes.io/storage-provisioner 键（由卷控制器创建），且其值是否与 Provisioner 名称相等。
  • PVC 对应 StorageClass 的 VolumeBindingMode 字段若为 WaitForFirstConsumer，则 PVC 的 annotation 中必须包含 volume.kubernetes.io/selected-node 键且值不为空；若为 Immediate 则表示需要 Provisioner 立即提供动态存储卷。
  • 满足条件后，通过 Unix Domain Socket 调用 CSI 插件的 CreateVolume 函数，并创建 PV 资源，PV 名称为 [Provisioner 指定的 PV 前缀]-[PVC uuid]。

对于 PV 资源，判断其是否需要删除：

  • 判断其 .Status.Phase 是否为 Released。
  • 判断其 .Spec.PersistentVolumeReclaimPolicy 是否为 Delete。
  • 判断其是否包含 annotation pv.kubernetes.io/provisioned-by，且值是否为自己。
  • 满足条件后，通过 Unix Domain Socket 调用 CSI 插件的 DeleteVolume 接口，并删除集群中的 PV 资源。

3. External Attacher

功能：挂接/摘除存储卷。

原理：内部会时刻 watch 集群中的 VolumeAttachment 资源和 PersistentVolume 资源。

对于 VolumeAttachment 资源：

  • 从中获得 PV 的所有信息，如 volume ID、node ID、挂载 Secret 等。
  • 通过 DeletionTimestamp 字段是否为空判断是卷挂接还是卷摘除：
    • 卷挂接：通过 Unix Domain Socket 调用 CSI 插件的 ControllerPublishVolume 接口。
    • 卷摘除：通过 Unix Domain Socket 调用 CSI 插件的 ControllerUnpublishVolume 接口。

对于 PersistentVolume 资源：

  • 在挂接时为相关 PV 打上 Finalizer：external-attacher/[driver 名称]。
  • 当 PV 处于删除状态时（DeletionTimestamp 非空），删除该 Finalizer。

4. External Resizer

功能：扩容存储卷。

原理：内部会 watch 集群中的 PersistentVolumeClaim 资源。

  • 判断 PVC 是否需要扩容：状态需为 Bound 且 .Status.Capacity 与 .Spec.Resources.Requests 不等。
  • 更新 PVC 的 .Status.Conditions，表明处于 Resizing 状态。
  • 通过 Unix Domain Socket 调用 CSI 插件的 ControllerExpandVolume 接口，并更新 PV的 .Spec.Capacity。
  • 若 CSI 支持文件系统在线扩容：ControllerExpandVolume 返回值中 NodeExpansionRequired 为 true，将 PVC 的 .Status.Conditions 置为 FileSystemResizePending；随后 kubelet 的 Volume Manager 观察到需在线扩容，通过 Unix Domain Socket 调用 CSI 插件的 NodeExpandVolume 接口完成文件系统扩容。
  • 若不支持在线扩容，则扩容直接完成，清空 PVC 的 .Status.Conditions 并更新 .Status.Capacity。

5. External Snapshotter

功能：管理存储卷快照。

原理：watch 集群中的 VolumeSnapshot、VolumeSnapshotContent 资源，通过 Unix Domain Socket 调用 CSI 插件的 CreateSnapshot、DeleteSnapshot 接口，实现快照的创建与删除。该能力现已 GA。

6. Livenessprobe

功能：检查 CSI 插件是否正常。

原理：对外暴露一个 /healthz HTTP 端口以服务 kubelet 的探针，内部通过 Unix Domain Socket 调用 CSI 插件的 Probe 接口。

六、CSI 与 Kubernetes 组件的通信方式

  • CSI Controller 与 Kubernetes 的通信：external-provisioner、external-attacher 等 Sidecar 容器通过 Kubernetes API 监听资源对象的变化（如 PVC、VolumeAttachment），并通过 Unix Domain Socket 调用 CSI 驱动的接口。
  • CSI Node 与 kubelet 的通信：node-driver-registrar 通过 Unix Domain Socket 与 kubelet 通信；CSI Driver 容器通过 Unix Domain Socket 接收 kubelet 的调用，完成存储卷的挂载和卸载。
  • CSI 驱动与 Sidecar 的通信：通过 Unix Domain Socket 使用 gRPC 协议进行通信，Sidecar 容器通过 gRPC 调用 CSI 驱动的接口，完成具体的存储操作。

七、CSI 工作原理

CSI 的工作流程围绕 Kubernetes 的存储资源（如 PersistentVolume、PersistentVolumeClaim）展开，主要包含以下步骤：

  1. 存储资源的创建：用户创建 PVC，指定存储需求（大小、访问模式等）。external-provisioner 监听到 PVC 变化，调用 CSI 驱动的 CreateVolume 接口创建存储卷。
  2. 存储卷的挂载：external-attacher 监听到 VolumeAttachment 变化，调用 CSI 驱动的 ControllerPublish 接口将存储卷与目标节点绑定；kubelet 通过 node-driver-registrar 调用 CSI 驱动的 NodePublishVolume 接口，将存储卷挂载到容器的指定路径。
  3. 存储卷的卸载：用户删除 PVC 或 VolumeAttachment。external-attacher 调用 ControllerUnpublish 接口解除存储卷与节点的绑定；kubelet 调用 NodeUnpublishVolume 接口将存储卷从容器中卸载。
  4. 存储卷的删除：external-provisioner 监听到 PVC 的删除操作，调用 CSI 驱动的 DeleteVolume 接口删除存储卷。

    B --> C[创建 PV 资源]

八、CSI 与 FlexVolume 的对比

CSI 是 FlexVolume 的升级版，主要区别如下：

对比项 FlexVolume CSI
接口标准化 接口有限 标准化接口，支持快照、扩容等复杂操作
组件设计 耦合较紧 分离为 Controller 和 Node 两部分，部署与扩展更灵活
通信协议 依赖可执行文件调用 使用 gRPC 协议，通信效率更高

九、小结

CSI 是 Kubernetes 中存储管理的重要组成部分，通过标准化的接口和灵活的组件设计，为用户提供了强大的存储管理能力。它以 IdentityServer、ControllerServer、NodeServer 三大接口为核心，配合 external-provisioner、external-attacher、external-resizer、external-snapshotter 等 Sidecar 组件，把创建、挂载、卸载、扩容、快照等能力标准化。掌握 CSI 的工作原理和组件构成，能够帮助我们更好地管理和优化集群中的存储资源。
