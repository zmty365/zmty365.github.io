Kubernetes CNI 详解：网络模型、工作原理与主流插件

发表于2026-08-06|Kubernetes
|总字数:1.7k|阅读时长:5分钟|浏览量:

一、CNI 概述

Container Network Interface（CNI） 是由 CNCF（Cloud Native Computing Foundation）维护的开源项目，旨在为容器提供一致的网络配置接口。CNI 定义了一组规范和插件，使容器运行时（如 containerd、CRI-O 等）能够与第三方网络插件（CNI 插件）通信，从而实现容器网络的配置和管理。

Kubernetes 集群内的网络模型定义了以下几点：

  • 每个 Pod 都有独立的 IP 地址：Pod 内所有容器共享同一个网络命名空间，因此共享同一个 IP 和网络配置。
  • 集群内 Pod 处于扁平网络：所有 Pod 可直接互相通信，无需经过 NAT。
  • Service 与 Cluster IP：Kubernetes 提供 Service 和 Cluster IP，使服务能在集群内被发现和访问。
  • 外部访问：外部请求可通过 NodePort、LoadBalancer 或 Ingress 等方式访问集群内服务。

二、CNI 的工作原理

CNI 的核心思想是把容器的网络配置与容器运行时解耦，通过插件机制实现网络配置的灵活性。工作流程大致分为以下几步：

  1. 容器运行时创建网络命名空间：当 Kubernetes 把一个 Pod 调度到某节点时，容器运行时会为该 Pod 创建一个新的网络命名空间。
  2. CNI 插件进行网络配置：容器运行时调用 CNI 插件执行网络配置，插件负责：
    • 为容器分配 IP 地址；
    • 设置网络接口（如虚拟网卡）；
    • 配置路由表和网络策略。
  3. IPAM 插件分配 IP：CNI 插件通常使用 IPAM（IP Address Management）插件为容器分配 IP。IPAM 负责管理 IP 地址池，为每个容器分配唯一 IP。
  4. 启动容器：网络配置完成后，容器运行时启动容器，并将其加入已配置的网络命名空间。

三、CNI 插件的分类

按网络实现方式，CNI 插件大致可分为四类。

（1）二层互联：基于 VLAN 或 MAC 地址的二层网络技术。

  • 优点：网络延迟低，适合小规模集群。
  • 缺点：需在物理网络配置 VLAN，管理复杂，不适合跨机房或大规模集群。
  • 适用场景：小型集群或对网络性能要求较高的场景。

（2）三层路由：基于 BGP 等三层路由协议，通过路由表实现容器间通信。

  • 优点：传输效率高，无需封装 / 解封装。
  • 缺点：路由配置复杂，可能需要额外硬件支持。
  • 适用场景：大规模集群，尤其需要高性能网络的场景。

（3）Overlay 方案：通过 VXLAN、IPIP 等协议把容器网络封装在现有物理网络之上。

  • 优点：支持跨数据中心互联，配置相对简单。
  • 缺点：封装 / 解封装会增加一定计算和网络延迟。
  • 适用场景：跨数据中心或混合云环境。

（4）SDN 方案：基于软件定义网络，使用 SDN 控制器和虚拟交换机（如 OVS）实现灵活配置。

  • 优点：高度可定制，支持复杂网络策略。
  • 缺点：架构复杂，部署和维护成本较高。
  • 适用场景：对网络策略和定制化需求较高的企业级应用。

四、常见的 CNI 插件

1. Calico

特点：

  • 基于 BGP 的网络方案：使用 BGP 协议实现容器间路由，支持大规模集群。
  • 强大的网络策略：支持基于 IP、端口、协议的细粒度策略，安全功能丰富。
  • 高性能与扩展性：适用于大规模集群。
  • 多种网络模式：支持 Overlay 和 Underlay，适应不同网络环境。

应用场景：适用于金融、电信等对网络安全和策略管理要求较高的行业，以及大规模集群和混合云环境。

2. Flannel

特点：

  • 简单易用：最早被广泛使用的 CNI 插件之一，配置简单，适合快速部署。
  • 多种后端驱动：支持 VXLAN、host-gw 等多种后端，适应不同网络环境。
  • 低资源消耗：资源占用较低，适合轻量级生产环境。

应用场景：适用于初学者和测试环境，以及对网络功能要求较低的生产环境。

3. Canal

特点：

  • 结合 Calico 和 Flannel 的优势：兼具 Calico 的网络策略与 Flannel 的简单易用。
  • 强大的网络隔离：支持细粒度网络策略，同时保持较低的配置复杂度。
  • 适合混合环境：适用于既需要高性能又希望配置简单的场景。

应用场景：适用于既需要强大网络安全策略、又希望配置简单的场景，常见于混合云和企业内部云原生平台。

六、CNI 的高级主题

  • 多租户网络：CNI 插件支持多租户网络，通过网络策略和隔离机制实现不同租户之间的网络隔离。
  • 网络策略：Kubernetes 提供 NetworkPolicy 资源，结合 CNI 插件的网络策略功能，可实现细粒度的网络访问控制。
  • 性能优化：
    • 根据集群规模和网络需求，选择合适的 CNI 插件与网络方案。
    • 配置合适的网络参数（如 MTU、路由表等）以优化网络性能。

七、小结

  • CNI 是 Kubernetes 网络模型的核心组件，通过插件机制把容器网络配置与运行时解耦，实现灵活的网络配置与管理。
  • 按实现方式可分为二层互联、三层路由、Overlay、SDN 四类，各有适用规模与场景。
  • 主流插件中：Calico（BGP，强策略，大规模）、Flannel（简单轻量）、Canal（Calico + Flannel 组合）各有侧重。
  • 选型时应结合集群规模、性能要求与网络策略需求综合权衡，安装请以官方最新文档为准。
